# 추천상품 검색 품질 점검 메모

작성일: 2026-05-19

관련 문서: `docs/recommend_enrich_prompt_test_plan.md` — Claude 이미지 감사/최종 enrich 프롬프트와 오염 방지 테스트 기준

## 핵심 요약

현재 추천상품 프로토타입의 검색 품질은 `product_enriched`의 구조화 값과 `product_descriptions`의 4개 관점 임베딩 품질에 크게 좌우된다.

흐름은 대략 다음과 같다.

1. 상품 상세 페이지의 상품명, 본문 텍스트, 상세 이미지 수집
2. 멀티모달 LLM으로 상품 속성, 태그, 설명문 추출
3. `product_enriched`에 구조화 데이터 저장
4. `desc_situation`, `desc_material`, `desc_style`, `desc_persona`를 임베딩
5. `product_descriptions` 벡터 검색
6. 검색어를 LLM이 `semantic_query`, 정형 필터, 키워드 필터로 변환
7. 벡터 검색 + 필터 검색으로 상품 추천

연예인 검수 문제는 단독 이슈가 아니라, 검색에 들어가는 데이터 중 LLM이 잘못 추출하거나 모르는 정보를 그대로 임베딩하는 문제의 대표 케이스다.

## 특히 위험한 지점

- `desc_*` 설명문에 틀린 정보가 들어가면 임베딩이 오염된다.
- `tags`에 틀린 고유명사, 소재, 기능, 마케팅 문구가 들어가면 하드필터 검색이 오염된다.
- `category`가 정규화되지 않으면 같은 상품군이 여러 카테고리로 갈라진다.
- `brand`가 정규화되지 않으면 같은 브랜드가 여러 이름으로 갈라진다.
- `target_gender`는 구매자 성별이어야 하는데, 연예인/모델 성별과 섞일 수 있다.
- SET 상품은 구성품, 착용컷, 추천상품, 관련상품 정보가 본상품 속성으로 섞일 수 있다.
- `keyword_filters`가 0건 결과를 만들면 서버가 필터를 완화할 수 있어서, 반드시 맞아야 하는 조건이 풀릴 수 있다.
- 검수 후 재임베딩을 BGE만 하면 OpenAI 벡터 검색 결과와 BGE 검색 결과가 달라질 수 있다.

## 실제로 의심되는 데이터 패턴

- 카테고리 과분화: `귀걸이`, `귀고리`, `후프`, `호프`, `SET`, `세트`, `셋트`, `팬던트`, `펜던트`, `네클리스`, `넥클리스`
- 브랜드 표기 분산: `LUVRE PARIS`, `루브르파리`, `Luvreparis`, `LOUVRE PARIS`, `LUUVRE PARIS`, `Luv Re Paris`
- 태그 스키마 이탈: `style`, `material`, `persona` 같은 비표준 tag_category
- 과장 문구: `완벽`, `강력히 추천`, `필수 아이템`, `명품`, `럭셔리`, `투자 가치`, `인기`
- 오타/비문: `특별한 날씨`, `민성 디자인`, `프리미엠`, `미니몰`
- 근거 확인 필요 문구: `백화점 정품`, `니켈프리`, `알러지프리`, `피부친화`

## 조회할 때 볼 항목

검색 결과만 보지 말고 아래 값을 같이 확인한다.

- `parsed.semantic_query`
- `parsed.filters`
- `keyword_filters_applied`
- `keyword_filter_relaxed`
- `pe_filter_relaxed`
- top result의 `product_name`
- top result의 `category`
- top result의 `tags`
- top result의 `desc_persona`
- top result의 `description`

특히 특정 연예인, 특정 소재, 특정 가격, 특정 세트 구성처럼 반드시 맞아야 하는 쿼리에서 `keyword_filter_relaxed=true` 또는 `pe_filter_relaxed=true`가 나오면 그 지점이 새는 것이다.

## 빠른 판정 기준

### 연예인/고유명사

- 특정 이름이 들어간 쿼리는 `keyword_filters_applied`에 그 이름이 있어야 한다.
- 특정 이름으로 검색했는데 0건이라서 필터가 풀리면 안 된다.
- `남자연예인 착용`, `여자연예인 착용`은 `target_gender`로 가면 안 된다. 구매자 성별이 아니라 착용자 성별이다.

### 카테고리

- `귀걸이`, `귀고리`, `이어링`은 같은 의도로 묶여야 한다.
- `팬던트`, `펜던트`, `넥클리스`, `네클리스`는 같은 의도로 묶여야 한다.
- SET 상품은 실제 구성품과 category가 일치해야 한다.

### 소재/스톤

- `14K 골드`, `14K 도금`, `14K 골드필드`, `925 실버`는 서로 섞이면 안 된다.
- `큐빅`을 `다이아몬드`로 검색했을 때 상위에 과하게 뜨면 위험하다.
- `진주`와 `인공진주`는 가능하면 구분되어야 한다.

### 마케팅/검증 문구

- `백화점 정품`, `명품`, `인기`, `강력 추천`, `완벽`, `투자 가치`는 근거가 없으면 검색 문서에 들어가면 안 된다.
- 이런 단어가 많은 상품이 상위에 뜨면 설명문 생성이 광고 문구 쪽으로 새고 있는 것이다.

### 가격/프로모션

- 상품명에 들어간 `6,900원`, `특가`, `당일출고`, `무료배송`과 실제 DB 가격/배송 정보가 일치하는지 확인해야 한다.
- 현재 가격 필터는 검색 파서에서 완전한 정형 필터로 처리되지 않을 수 있으므로 별도 확인이 필요하다.
