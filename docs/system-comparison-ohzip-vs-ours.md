## 1. 모델 기반

| 항목 | 오늘의집 | 우리 시스템 |
|------|---------|------------|
| 베이스 모델 | BGE-M3 (도메인 파인튜닝) | BGE-M3 (base, 파인튜닝 없음) |
| 임베딩 차원 | **128d** (Matryoshka로 압축) | **1024d** (풀 차원 그대로) |
| 학습 방식 | 사용자 클릭·인터랙션 기반 파인튜닝 | 없음 |
| Sparse 검색 | 운영 중 | 백필 완료, 검색 통합 진행 중 |

**Matryoshka Representation Learning(MRL)** 이 핵심 차이.
1024d → 128d로 줄여도 성능 손실이 거의 없음. 우리는 1024d 그대로 쓰기 때문에
벡터 비교 연산량이 8배 많고, pgvector 풀스캔 속도도 그만큼 느림.

## 2. 인퍼런스(추론) 속도

| 항목 | 오늘의집 | 우리 시스템 |
|------|---------|------------|
| 임베딩 서버 | Text Embeddings Inference (TEI, Rust 엔진) | uvicorn + SentenceTransformer |
| 하드웨어 | GPU | **CPU만** |
| 쿼리 임베딩 속도 | **평균 4~6ms** | 수백ms ~ 수초 (첫 호출 시 모델 로딩 포함) |

검색이 느린 **가장 큰 원인**. TEI는 HuggingFace가 만든 Rust 기반 고성능 서빙 엔진으로
GPU 가속 + 배치 최적화를 지원. 우리는 CPU로 2.3GB 모델을 돌리고 있어서
근본적 한계가 있음.

## 3. 쿼리 파이프라인 & LLM 활용

| 항목 | 오늘의집 | 우리 시스템 |
|------|---------|------------|
| LLM 역할 | **오프라인 학습** (학습 데이터 자동 생성) | **온라인 런타임** (쿼리 파싱·필터링) |
| 쿼리 이해 방식 | 파인튜닝된 임베딩 자체 품질로 커버 | LLM이 쿼리 구조화 → 필터 적용 후 벡터 검색 |
| LLM 호출 타이밍 | 검색 시 없음 (학습 때만) | 매 검색마다 호출 (지연 발생) |

오늘의집: LLM을 "모델 품질 개선"에 투자 → 검색 자체가 빠름  
우리: LLM을 "런타임 쿼리 보정"에 활용 → 파인튜닝 없이도 의도 파악 가능,
단 매 검색마다 LLM 지연이 추가됨.

### 오늘의집 Model-in-the-Loop

```
임의 문서 선택
  → LLM이 관련 검색어 생성
  → 임베딩 모델이 후보 문서 추출
  → LLM이 후보 재정렬·점수 부여
  → 재정렬 결과를 학습 데이터로 모델 업데이트
  → 반복
```

항상 Positive 샘플 1개 이상 확보 보장, 지속적 자동 개선 사이클.

## 4. 설명력(Explainability)

| 항목 | 오늘의집 | 우리 시스템 |
|------|---------|------------|
| 방식 | ColBERT 토큰 히트맵 | 3D PCA 시각화 |
| 설명 단위 | 토큰(단어) 수준 — "왜 이 단어가 매칭됐나" | 벡터 공간 수준 — "전체 상품 유사도 분포" |
| LLM 추천사유 | 없음 | 있음 (자연어 추천사유 생성) |

ColBERT: "2겹" ↔ "이중", "유리잔" ↔ "유리컵" 같은 의미 매칭을 토큰별로 히트맵으로 보여줌.  
우리: 코사인 거리를 3D 구에 투영해 유사도 분포를 시각화, LLM이 추천 이유를 자연어로 설명.

## 5. 우리 시스템만 있는 강점

| 강점 | 설명 |
|------|------|
| **4관점 텍스트** | 기능성·감성·스타일·상황 4가지로 상품 설명. 단일 쿼리로 다양한 맥락 커버 |
| **3D 임베딩 시각화** | 검색 결과의 유사도 공간을 실시간 인터랙티브하게 표시 |
| **LLM 추천사유** | "왜 이 상품인지" 자연어로 설명 (오늘의집엔 없음) |
| **검색 이력 재현** | 과거 검색을 3D 그래프 포함 그대로 복원 |

## 6. 개선 로드맵

### 단기 (지금 바로 가능)

- **Hybrid Search 완성**: sparse 백필 완료 → α-가중합 검색 통합. 오늘의집도 BM25+dense 하이브리드 사용.
- **차원 축소 실험**: MRL 재학습 없이 1024d → 앞 256~512d만 잘라 저장/검색. 연산량 2~4배 감소.

### 중기 (GPU 또는 서버 확충 시)

- **TEI 도입**: Hugging Face Text Embeddings Inference로 교체 → 임베딩 속도 10~20배 개선.
- **BGE-M3 파인튜닝**: `search_logs` 클릭 데이터 + LLM 자동 레이블링으로 도메인 파인튜닝.
- **Model-in-the-Loop**: 오늘의집 방식 적용 — LLM으로 positive/negative 자동 생성 후 주기적 파인튜닝.

### 장기

- **MRL 적용**: 파인튜닝 시 Matryoshka 학습 → 128d로 운영해 인덱스 크기·속도 대폭 개선.
- **이미지 임베딩 연결**: 오늘의집도 목표로 하는 멀티모달 확장.

## 요약

| 관점 | 오늘의집 | 우리 시스템 |
|------|---------|------------|
| 전략 | 모델 자체를 도메인에 최적화 | LLM으로 런타임 커버 |
| 강점 | 빠른 인퍼런스, 낮은 차원, 자동 개선 루프 | 4관점, LLM 추천사유, 시각화, 파인튜닝 비용 없음 |
| 약점 | 학습 파이프라인 구축 필요 | CPU 인퍼런스 느림, 매 검색마다 LLM 지연 |
| 규모 | 수백만 상품, 다국어 | 수천~수만 상품, 단일 도메인 |

가장 빠른 개선 효과: **Hybrid Search 통합** + (가능하다면) **GPU 인퍼런스 서버**.
